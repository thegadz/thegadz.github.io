One-Page PRD · v1 · untuk pembeli asli

Top-up game lokal, checkout di bawah 60 detik.

Storefront top-up game Indonesia dengan harga Rupiah, pembayaran lokal, konfirmasi nickname, dan invoice yang bisa dilacak tanpa akun. Target: pembeli asli bisa menyelesaikan pesanan dalam satu menit dan percaya bahwa ID-nya benar.

8 game × 6 SKU Guest-only Light marketplace Cloudflare $0/mo Checkout < 60s

Bagian 1

Ringkasan & tujuan

GadzStore v1 adalah storefront top-up game Indonesia untuk pembeli asli — bukan mockup untuk dipamerkan, tapi produk yang bisa dipakai orang untuk benar-benar memesan. Anggap ini validasi bisnis: apakah alur beli kita cukup cepat, jelas, dan dipercaya?

Tujuan #1

Checkout di bawah 60 detik

Dari buka halaman sampai kode order keluar. Diukur di HP, pakai satu tangan. Ini metrik utama v1.

Tujuan #2

Nol salah ID

Pembeli harus melihat nickname-nya sendiri sebelum bayar. Salah ID adalah keluhan #1 di usaha top-up mana pun.

Tujuan #3

Bisa dilacak tanpa akun

Kode order + halaman Cek Order. Tanpa login, tanpa password, tanpa email.

🎯
Bukan tujuan v1 (dan ini disengaja)

Uang sungguhan, akun pengguna, refund otomatis, integrasi WhatsApp bot, multi-bahasa, stok terbatas. Semua itu menambah biaya dan risiko tanpa menambah bukti validasi. v1 membuktikan alur dan kepercayaan dulu.

Bagian 3

Dua keberatan PM (kamu yang putuskan)

Saya setuju dengan 6 dari 8 keputusan. Dua ini berisiko terhadap pembeli asli, jadi saya tulis apa adanya beserta usulan komprominya.

⚠️
Keberatan 1 — "Simulasi notifikasi WA/email"

Pembeli asli akan menunggu pesan yang tidak pernah datang, lalu menghubungi CS dengan marah. Ini justru merusak kepercayaan yang jadi tujuan #2 kita. Kalau ada yang screenshots lalu ditunjukkan ke orang lain, klaimnya juga tidak jujur.

Usulan kompromi (rekomendasi saya): tombol "Kirim invoice ke WhatsApp saya" — membuka wa.me dengan teks invoice sudah terisi (kode order, game, nominal, total). Terasa seperti notifikasi, tapi jujur: pembeli sendiri yang mengirim. Biaya build: ~0. Kalau kamu tetap mau simulasi penuh, wajib berlabel "DEMO — notifikasi tidak benar-benar dikirim" di setiap titik.

⏱️
Keberatan 2 — "Order Pending dibiarkan, admin bersihkan manual"

Tanpa auto-expire, invoice dengan QRIS yang sudah kedaluwarsa tetap tampil "menunggu pembayaran". Pembeli asli bisa memindai QR mati, uang tidak masuk, dan mereka menyalahkan kita.

Usulan kompromi (rekomendasi saya): status di database tetap pending sesuai keputusanmu, tapi tampilan invoice berubah jadi "Kedaluwarsa" begitu timer 15 menit habis. Nol otomasi server, nol cron, tapi pembeli tidak pernah menyesatkan. Admin tetap bisa membersihkan kapan saja.

✓
Catatan badge kepercayaan

Badge yang saya sarankan: "Top-up instan 24/7", "Pembayaran lewat QRIS & e-wallet", "Cek status kapan saja dengan kode order". Saya tidak memakai "50.000+ transaksi" atau "sejak 2021" — angka palsu mudah terbongkar oleh pembeli asli dan merusak tujuan #2.

Bagian 4

Scope: masuk vs keluar

✓ Masuk v1

  • Home — banner, 8 game, pencarian, trust strip
  • Halaman game — art, rating, ID + Zone, Verify ID
  • Checkout — 6 SKU, metode bayar + biaya admin terpisah
  • Invoice — kode order, QRIS, timer 15 menit, tombol simulasi bayar
  • Cek Order — lacak by kode, timeline status
  • Admin /admin — password, tabel order + filter, ubah status, edit harga/SKU, upload banner
  • Seed data — 8 game, 48 SKU, 5 metode bayar

✗ Keluar dari v1

  • Login / akun / password reset
  • Payment gateway sungguhan (Midtrans/Xendit — butuh KYC)
  • WhatsApp bot, email transaksional
  • Refund, retry bayar, kode promo bertumpuk
  • Stok terbatas, wishlist, ulasan, multi-bahasa
  • Auto-expire order (keputusanmu — pakai penjaga tampilan)

Bagian 6

Acceptance criteria

Ditulis sebagai perilaku yang bisa dicek mata dan bisa dites otomatis. Format: Given → When → Then.

A. Verifikasi ID (US-03, US-04, US-05)

SkenarioDiterima bila
ID kosongTombol Verify ID disabled (warna abu); tidak ada request ke server.
ID bukan angkaError inline "Player ID hanya angka" di bawah input, border input merah.
ID terlalu pendek (< 6 digit)Error inline "Player ID minimal 6 digit". Tombol tetap disabled.
Game butuh Zone (MLBB, Genshin)Field Zone wajib tampil; kalau kosong → "Zone ID wajib diisi".
Verifikasi berhasilDalam < 1,5 detik tampil kartu berisi avatar inisial, nickname, dan "Akun ditemukan". Tombol berubah jadi "Ganti ID".
Verifikasi gagal (simulasi)Kartu merah "Akun tidak ditemukan. Periksa ID & Zone kamu." + tombol Coba lagi. CTA Bayar tetap terkunci.
Mengubah ID setelah verifikasiNickname lama hilang, CTA Bayar terkunci lagi sampai verifikasi ulang. Wajib — mencegah bayar dengan ID baru tanpa cek.
Peringatan ID salahMuncul tepat di atas CTA Bayar, tidak bisa di-dismiss: "Pastikan ID & nickname benar. Top-up ke ID salah tidak dapat direfund."

B. Checkout & harga (US-06, US-07)

SkenarioDiterima bila
Belum pilih SKUCTA disabled; teks CTA "Pilih nominal dulu".
Pilih SKUSatu tap memilih; SKU sebelumnya otomatis lepas. Ringkasan bawah update < 100ms.
Biaya adminRincian selalu terpisah 3 baris: Harga item, Biaya admin, Total. QRIS Rp0 · GoPay/OVO/DANA/ShopeePay Rp1.500 · VA Rp2.500.
DiskonHarga asli dicoret + badge -10%; total pakai harga diskon. Tidak ada kode promo di v1.
Harga dihitung serverTotal di invoice harus sama dengan hitung server. Perubahan harga dari client ditolak (400).

C. Invoice & status (US-08 s/d US-12)

SkenarioDiterima bila
Order dibuatKode GB-YYMMDD-XXXX, URL invoice bisa dibuka ulang tanpa login, status PENDING.
TimerHitung mundur dari 15:00, format mm:ss, tetap akurat setelah refresh (dihitung dari expires_at).
Timer < 3 menitPill timer kekuningan dan berdenyut halus (tanpa suara).
Timer habisBlok QRIS jadi abu-abu + label "Kedaluwarsa"; tombol simulasi bayar disabled. Status DB tetap pending.
Simulasi bayarSetelah diklik: status jadi PAID, timeline bergerak, tombol hilang, muncul "Lihat status pesanan".
Cek OrderKode salah → "Kode order tidak ditemukan" (bukan halaman kosong). Kode benar → timeline 3 langkah, data akun game, total.
Kirim ke WhatsAppMembuka wa.me dengan pesan terisi: kode order, game, SKU, ID/Zone, total. Tidak ada pengiriman otomatis dari server.

D. Admin (US-15 s/d US-20)

SkenarioDiterima bila
Akses tanpa login/admin menampilkan form password; tidak ada data order di HTML awal.
Password salah 5×Ditolak dengan jeda bertambah (rate limit); tidak ada petunjuk password.
Filter statusTab Semua / Pending / Paid / Completed / Cancelled + pencarian kode. Hasil < 500ms.
Ubah statusHanya transisi valid: Pending→Paid→Completed, plus Cancel dari Pending. Tombol tidak valid tidak tampil.
Edit hargaTersimpan ke D1, langsung terlihat di storefront setelah refresh; harga tidak boleh ≤ 0.
Upload bannerHanya JPG/PNG/WebP, maks 2MB; file masuk R2, beranda memakai URL baru.
📐
Batas keras v1

Maksimal 3 langkah dari halaman game ke invoice. Maksimal 2 input sebelum bayar (ID + Zone). Tidak ada perpindahan halaman di dalam checkout. Kalau sebuah fitur menambah langkah atau layar, fitur itu tidak masuk v1.

Spesifikasi komponen

  • Tombol primary — tinggi 48px, radius 12px, teks 15px/800, shadow ungu lembut. Satu per layar.
  • Tombol secondary — outline ungu, latar putih, tinggi 44px.
  • Input — tinggi 48px, radius 10px, border #E4E8F2, focus ring ungu 2px.
  • Kartu SKU — radius 12px, padding 12px, border 1.5px; terpilih = border ungu + latar ungu muda.
  • Baris metode bayar — ikon 26×20, nama, biaya admin rata kanan.
  • Badge status — pill radius 999, teks 11px/700, titik 6px di kiri.
  • CTA sticky — menempel di bawah, latar putih, garis atas, padding 12px.
📏
Aturan sentuhan (target jempol)

Semua elemen yang bisa ditekan minimal 44×44px. CTA utama selalu di zona jempol bawah, tidak pernah di atas lipatan. Jarak antar tombol minimal 8px supaya tidak salah tap. Form ID + Zone: input pertama auto-focus dan keyboard angka langsung terbuka (inputmode="numeric").

Bagian 9

Wireframe per layar

Catatan tata letak per layar, urutan dari atas ke bawah (mobile-first, 390px). Angka di kurung = prioritas visual (1 paling menonjol). Layar yang punya mock interaktif penuh ada di §10.

LAYAR 1 · HOME

Siapa kamu, mau main apa

(1)Top bar — logo GadzStore kiri, tombol "Cek Order" kanan (ikon + teks, 12px).
(2)Trust strip — 3 badge horizontal: "Instan 24/7", "QRIS & e-wallet", "Lacak dengan kode". Teks 11px, tanpa gambar berat.
(3)Banner — satu kartu gradient ungu→cyan, tinggi ~96px, teks promo + CTA kecil. Bisa diganti admin lewat R2.
(4)Pencarian — kotak bulat, placeholder "Cari game…". Filter instan saat mengetik.
(5)Grid game — 3 kolom × 3 baris (8 game). Kartu: art, nama 1 baris, "mulai Rp…". Tap → halaman game.
(6)Footer mini — "Butuh bantuan? WhatsApp CS" + disclaimer "Situs demo".

Yang sengaja tidak ada: carousel auto-play, pop-up promo saat masuk, 5 banner bertumpuk, footer panjang berisi link mati.

LAYAR 2 · GAME + VERIFY

Layar paling penting di toko ini

(1)Header game — art 56×56, nama game, rating kecil, latar kartu putih.
(2)Input Player ID — label jelas, hint "Ada di profil game kamu", keyboard angka.
(3)Input Zone — hanya muncul untuk game yang butuh (MLBB, Genshin).
(4)Tombol Verify ID — full width, disabled sampai ID valid.
(5)Kartu nickname — hijau, avatar inisial, nama, "Akun ditemukan ✓". Menggantikan area input setelah sukses, dengan link "Ganti ID".
(6)Sisa langkah — setelah verify: "Nominal" grid 2 kolom, lalu "Metode bayar". Tersembunyi sebelum verify supaya pembeli tidak melompati konfirmasi.
(7)Warning ID salah — bar merah tipis tepat di atas CTA.
(8)CTA sticky — "Bayar RpX" + total, selalu terlihat.

Kunci UX: nominal & metode bayar baru muncul setelah nickname terkonfirmasi. Satu arah, tidak bisa dilewati.

LAYAR 3 · INVOICE / QRIS

Tempat pembeli kehilangan kepercayaan

(1)Status badge besar: "Menunggu pembayaran" (kuning) + timer mono 15:00.
(2)Kode order — mono, besar, dengan ikon salin. Ini identitas pesanan.
(3)QRIS — QR hitam-putih asli, label "QRIS (demo)".
(4)Rincian — game, SKU, ID/Zone, nickname, harga item, biaya admin, total.
(5)Aksi — "Simulasi sudah bayar" (outline), "Kirim invoice ke WhatsApp saya".
(6)Setelah lunas — QR hilang, diganti timeline 3 langkah + tombol "Lihat status pesanan".

Setelah 15 menit: blok QR jadi abu-abu berlabel "Kedaluwarsa", tombol bayar mati, muncul "Buat pesanan baru".

LAYAR 4 · CEK ORDER

Pengganti akun

(1)Input kode order — mono, auto-uppercase, format hint GB-YYMMDD-XXXX.
(2)Hasil — kartu status + timeline vertikal 3 langkah (Dibuat → Dibayar → Selesai).
(3)Ringkasan pesanan — game, SKU, nickname, total, waktu dibuat.
(4)Bantuan — "Kode tidak ditemukan? Hubungi CS" dengan link wa.me berisi kode yang diketik.

Sengaja tanpa akun — halaman ini harus jalan dari link yang dibagikan orang lain, tanpa sesi.

LAYAR 5 · ADMIN

Meja kerja, bukan dashboard cantik

(1)Login — satu kolom password, satu tombol. Tidak ada "lupa password".
(2)Kartu hitung — 4 angka: Pending, Paid, Completed, Cancelled hari ini.
(3)Tab filter — Semua / Pending / Paid / Completed / Cancelled + kolom cari kode.
(4)Tabel order — kode, waktu, game, SKU, nickname, total, status badge, aksi.
(5)Aksi baris — hanya transisi valid: "Tandai Lunas", "Tandai Selesai", "Batalkan".
(6)Panel lain — Edit harga SKU, Upload banner. Dua tab, bukan halaman baru.

Prioritas mobile: admin sering buka dari HP — tabel jadi kartu bertumpuk di bawah 640px.

CATATAN LINTAS LAYAR

Aturan yang berlaku di semua layar

  • Kode order selalu bisa disalin dengan satu tap.
  • Harga selalu berformat Rp64.000 — titik ribuan, tanpa desimal.
  • Tidak ada modal/pop-up. Semua konfirmasi inline atau layar penuh.
  • Setiap layar punya jalan keluar jelas (back atau "Cek Order").
  • Loading state > 500ms wajib skeleton, bukan spinner kosong.

Bagian 15

Jebakan Junior PM

Lima kesalahan yang paling sering terjadi pada toko top-up pertama, ditulis sebagai gejala → akibat → tindakan.

1 · Menambahkan akun "biar rapi"

Gejala: "Kan enak kalau pembeli bisa lihat riwayat." Akibat: register, login, lupa password, verifikasi email — 4 layar baru dan 1 tabel baru, tanpa satu pun pembeli memintanya.

Tindakan: Cek Order dengan kode sudah menyelesaikan 100% kebutuhan "lihat riwayat". Tulis di PRD: akun = v2, dan hanya kalau ada ≥ 5 permintaan nyata.

2 · Menumpuk edge case sebelum ada 1 order

Gejala: refactor, promo code, cashback, multi-bahasa. Akibat: tidak ada yang bisa dibeli sampai minggu ke-6.

Tindakan: jadikan "ada 1 order pending yang bisa dibuka ulang lewat kode" sebagai gerbang pertama. Semua fitur lain menunggu gerbang itu lewat.

3 · Mengabaikan jempol dan keyboard

Gejala: desain indah di laptop, rusak di HP. Akibat: input ID di tengah layar, keyboard menutupi CTA, tombol 28px.

Tindakan: semua review dilakukan di HP 390px, bukan laptop. CTA sticky di bawah, input inputmode="numeric", target sentuh 44px.

4 · Scope creep lewat "cuma nambah satu field"

Gejala: email opsional, kode promo, catatan untuk admin. Akibat: setiap field baru menambah validasi, kolom DB, dan kasus uji — dan memperlambat checkout.

Tindakan: pakai batas keras §6: maksimal 2 input sebelum bayar. Field baru harus menghapus field lain, bukan menambah.

5 · Klaim kepercayaan yang tidak bisa dibuktikan

Gejala: "50.000+ transaksi", "sejak 2021", logo bank yang tidak dipakai. Akibat: begitu satu pembeli sadar itu palsu, seluruh halaman kehilangan kredibilitas.

Tindakan: hanya 3 badge jujur di §3. Label "DEMO" pada QRIS dan tombol simulasi tetap terlihat, seberapa pun inginnya dihapus.

Aturan penutup untuk dirimu

Sebelum menambah apa pun, jawab tiga pertanyaan ini di catatan:

  1. Cerita pengguna mana (US-xx) yang dilayani?
  2. Menambah langkah, layar, atau input?
  3. Bisa ditunda ke v2 tanpa merusak alur bayar?

Kalau jawaban (2) ya dan (3) ya — tunda.
